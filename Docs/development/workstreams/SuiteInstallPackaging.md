# Ethos Suite Install Packaging

**Target version:** 2.2
**Created:** 2026-09-29 · **Updated:** 2026-11-04
**Status:** Implemented — waiting for hardware verification (Suite install on the X20RS)
**Spec:** `Docs/development/tools/ethos_good_lua.md` (FrSky Local Lua Script Package Specification V1)

## Goal

Install through **Ethos Suite → Lua Library → Install from local `.zip`**, keep the manual SD-card
install, and get the widget into the official FrSky Lua library.

## What is in place

| Item | Implementation |
|---|---|
| UI icons | `src/scripts/ethosmaps/bitmaps/*.png`, loaded from `/scripts/ethosmaps/bitmaps/` (`drawlib.getBitmap()`, `tileloader` nomap/loading). The Suite can only install below `SCRIPTS:/{folder}/`. No fallback to the old `/bitmaps/ethosmaps/bitmaps/`. |
| Map tiles | unchanged, `/bitmaps/ethosmaps/maps/` (+ Yaapu fallback, `notiles.png` fallback) — user data, not in the package |
| Manifest | generated by `build/Build-Release.ps1`: `manifestVersion 1`, `name "ETHOS Mapping Widget"`, `key "com.github.b14ckyy.ethosmaps"`, `folder "ethosmaps"`, `version` = `WIDGET_VERSION`, `files ["main.lua","lib/*","audio/*","bitmaps/*"]`, `releaseNotes` = the `## x.y.z` section of `CHANGELOG.md` (markdown). UTF-8 without BOM. |
| Package identity | `key` and `folder` are fixed forever after the first Suite release. The widget key `ethosmw` is unrelated and stays. |
| Version rule | `WIDGET_VERSION` must be `x.y.z` numeric — the build fails otherwise. RC status goes into the release notes, not the version string. |
| ZIPs | `…-suite.zip`: manifest + `main.lua`, `lib/`, `audio/`, `bitmaps/` at ZIP root. `…-sdcard.zip`: `scripts/ethosmaps/…` incl. the manifest. Written with `System.IO.Compression` (forward slashes). |
| Build validation | Suite ZIP: manifest and `main.lua` at root, no backslashes or unsafe paths, every entry covered by `files`, `key`/`folder`/`name` match the spec rules. |
| Runtime files | `state.dat`, `debug.log` are never in `files`, so a Suite update does not delete them. |

## Hardware verification (maintainer)

1. Fresh install via Suite with the `-suite.zip` → `/scripts/ethosmaps/ethos_lua_manifest.json`
   written by the Suite, Lua Library shows name and version.
2. All icons visible (zoom ±, lock, pin, home, loading, nomap, GPS icons).
3. Update over an existing manual 2.1.0 install: settings and `state.dat` intact, widget works,
   old `/bitmaps/ethosmaps/bitmaps/` untouched (no longer used).
4. Second Suite install of the same package: no duplicate Lua Library entry (key matching).
5. `-sdcard.zip` extracted to the SD root: same checks as 2.

## Open questions

- Does the Lua Library show the manifest `name` or the `system.registerWidget` name? (docs wording)
- Requirements for the official FrSky library (icon, description, licence field?) — to be
  clarified with the ETHOS devs.
- Key namespace: FrSky's own packages use their domain (`org.frsky-ethos.elrs`,
  `org.frsky-ethos.crossfire`); third-party packages in the library keep their publisher key
  (e.g. `com.gib2a.ethos.power`). So no re-keying for the library — `com.github.b14ckyy.ethosmaps`
  stays. Third-party scripts are offered there as download with a version picker, not as direct
  install; users then install the downloaded ZIP via *Install from local `.zip`*.
- FrSky's packages use `files: ["**"]`. We keep the explicit list on purpose: it is unclear whether
  the Suite deletes "old files" on update by the stored pattern or by the expanded file list — with
  `**` evaluated against the radio folder, `state.dat` and `debug.log` would be at risk.
